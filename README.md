# Календарь для Telegram: мини-приложение + бот

Красивый календарь (месяц / неделя / день, 8 тем, настраиваемое скругление), бот с напоминаниями, работа в группах, оплата тарифов в Telegram Stars. Всё на бесплатных сервисах: GitHub Pages + Supabase.

```
Telegram ─┬─ бот (webhook) ──► Supabase Edge Function «bot»
          └─ Mini App (GitHub Pages) ──► функция «api» ──► Postgres
pg_cron (раз в минуту) ──► функция «cron» ──► уведомления в Telegram
Google OAuth ──► функция «google»      Apple/Google подписка ──► функция «ics»
```

## Что понадобится (всё бесплатно)

- аккаунт Telegram,
- аккаунт [GitHub](https://github.com) и [Supabase](https://supabase.com),
- Node.js 18+ на компьютере (для команды `npx supabase`),
- Google-аккаунт: только если включаете синхронизацию с Google (шаг 8).

Установка занимает около 30–40 минут. Идите по шагам.

---

## Шаг 1. Создайте бота

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → задайте имя и username (например, `my_calendar_bot`).
2. Сохраните **токен** (`123456:ABC...`) и username без `@`.
3. `/mybots` → ваш бот → **Bot Settings → Group Privacy → Turn off** (чтобы бот видел сообщения в группах).
4. Там же: **Allow Groups → Turn on** (по умолчанию включено).
5. Узнайте свой Telegram ID у [@userinfobot](https://t.me/userinfobot). Это `ADMIN_ID`.

## Шаг 2. База данных (Supabase)

1. На supabase.com → **New project**. Запомните **Project ref** (в адресе проекта: `https://supabase.com/dashboard/project/<REF>`).
2. Откройте **SQL Editor** → вставьте весь файл `supabase/migrations/001_init.sql` → **Run**.
3. Проверьте: в **Table Editor** появились таблицы, у каждой написано *RLS enabled*.

## Шаг 3. Секреты и функции

Сгенерируйте три случайные строки (в терминале): `openssl rand -hex 24` (запустите три раза) — это `WEBHOOK_SECRET`, `CRON_SECRET`, `TOKEN_KEY`. **Сохраните их в надёжном месте**: потеряв `TOKEN_KEY`, вы потеряете возможность читать токены Google (пользователям придётся подключить Google заново).

В папке проекта:

```bash
npx supabase login
npx supabase link --project-ref ВАШ_REF

npx supabase secrets set \
  BOT_TOKEN=123456:ABC... \
  BOT_USERNAME=my_calendar_bot \
  ADMIN_ID=ваш_telegram_id \
  WEBHOOK_SECRET=... \
  CRON_SECRET=... \
  TOKEN_KEY=... \
  APP_URL=https://ВАШ_GITHUB_ЛОГИН.github.io/НАЗВАНИЕ_РЕПОЗИТОРИЯ

npx supabase functions deploy bot api cron google ics --use-api
```

`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` Supabase подставляет сам, их вводить не нужно.

## Шаг 4. Мини-приложение на GitHub Pages

1. Создайте на GitHub публичный репозиторий и загрузите в него весь проект.
2. Откройте `docs/config.js` и замените `ВАШ_PROJECT_REF` на ваш Project ref. Сохраните (commit).
3. **Settings → Pages → Build from branch → `main` / папка `/docs` → Save.**
4. Через минуту приложение откроется по адресу из шага 3 (`https://логин.github.io/репозиторий`). Это и есть `APP_URL`.

Если вы открываете `index.html` просто в браузере (без Telegram), включается **демо-режим** с примерами: удобно посмотреть дизайн.

## Шаг 5. Подключите бота

```bash
BOT_TOKEN=... WEBHOOK_SECRET=... PROJECT_REF=... APP_URL=https://логин.github.io/репозиторий \
  ./scripts/setup-bot.sh
```

Скрипт ставит webhook, список команд и кнопку «Календарь» в меню бота.

Чтобы работала ссылка `t.me/ваш_бот?startapp` (кнопка «Открыть календарь» из групп): BotFather → `/mybots` → бот → **Bot Settings → Configure Mini App → Enable** → укажите `APP_URL`.

## Шаг 6. Планировщик уведомлений

Откройте `supabase/cron.sql`, замените `ВАШ_PROJECT_REF` и `ВАШ_CRON_SECRET`, вставьте в **SQL Editor** → **Run**.

## Шаг 7. Проверка

1. Откройте бота → `/start` → нажмите «Календарь».
2. Напишите: `добавь тест через 3 минуты`. Должно прийти подтверждение, а позже уведомление.
3. Добавьте бота в тестовую группу, напишите `добавь собрание завтра в 18:00`.
4. Отправьте боту `/stats` (команда только для вас).
5. Платежи: `/plan` → выберите тариф. Для проверки без оплаты используйте `/grant ваш_id pro 30`.

## Шаг 8 (по желанию). Синхронизация с Google Календарём

1. [console.cloud.google.com](https://console.cloud.google.com) → создайте проект → **APIs & Services → Library → Google Calendar API → Enable**.
2. **OAuth consent screen**: тип *External*, название, ваш email, ссылка на политику конфиденциальности (можно страница на вашем GitHub Pages).
3. **Scopes**: добавьте один — `.../auth/calendar.events`.
4. **Test users**: добавьте адреса Gmail тех, кто будет пользоваться (до 100).
5. **Credentials → Create credentials → OAuth client ID → Web application.**
   Authorized redirect URI: `https://ВАШ_REF.supabase.co/functions/v1/google`
6. Скопируйте Client ID и Client secret:

```bash
npx supabase secrets set GOOGLE_CLIENT_ID=... GOOGLE_CLIENT_SECRET=...
```

### Нужна ли «лицензия» Google?

Нет, лицензия не нужна. Это бесплатная **проверка приложения (OAuth verification)**: Google хочет убедиться, что вы честно описали, зачем просите доступ к календарю.

| Состояние | Что видят пользователи |
|---|---|
| **Testing** (по умолчанию) | Работает для добавленных вручную до 100 человек, **доступ сбрасывается каждые 7 дней** (нужно подключаться заново). |
| **Production, без проверки** | Любой может подключиться, но видит экран «Google не проверил это приложение» и лимит ~100 пользователей. |
| **Production, проверено** | Без предупреждений, без лимита. |

Для проверки Google просит: домен/страницу приложения, политику конфиденциальности, объяснение, зачем нужен доступ, и короткое видео, где показано, как приложение использует календарь. Платить не нужно. Обычно проходит за несколько дней или недель. Проверьте актуальные требования в консоли Google: со временем они меняются, а для адресов вида `*.github.io` Google иногда просит собственный домен.

**Как запуститься без ожидания:** переключите приложение на более узкий доступ `calendar.app.created`. Бот создаст отдельный календарь «Календарь из Telegram» и будет писать только в него. Доступ к вашим основным календарям не нужен, а такой доступ Google относит к менее чувствительным, так что проверка проще. Включается так (и в консоли Google в шаге 3 нужно выбрать этот scope):

```bash
npx supabase secrets set GOOGLE_SCOPE=https://www.googleapis.com/auth/calendar.app.created
```

В этом режиме события из вашего основного Google Календаря в приложении не появятся (только то, что создано через бота).

### Apple Календарь

Apple не даёт сторонним сервисам API для записи. Поэтому работает **подписка**: в приложении (Настройки → Подключения) копируете ссылку. На iPhone: *Настройки → Календарь → Учётные записи → Добавить → Другое → Подписной календарь*, вставьте ссылку. События из бота и приложения появляются в Apple Календаре и обновляются примерно раз в час. В обратную сторону, из Apple в бота, так не передать. Выход: экспортировать события из Apple Календаря в файл `.ics` и **отправить файл боту** — он их импортирует.

## Тарифы и Stars

Цены и лимиты — в одном файле `supabase/functions/_shared/plans.ts`. После правки: `npx supabase functions deploy bot api cron ics google --use-api`.

| | Free | Plus | Pro |
|---|---|---|---|
| Цена | 0 | 100 ⭐/мес · 1000 ⭐/год | 250 ⭐/мес · 2500 ⭐/год |
| Активных событий | 40 | без лимита | без лимита |
| Напоминаний на событие | 1 | 3 | 5 |
| Повторяющиеся события | нет | да | да |
| Темы | 2 | все 8 | все 8 |
| Подписка Apple / Google (ICS) | нет | да | да |
| Синхронизация с Google | нет | нет | да |
| Группы | 1 | 3 | без лимита |

Новым пользователям выдаётся пробный Pro на 7 дней (`TRIAL_DAYS` в `plans.ts`, `0` — отключить).

- Месяц — настоящая подписка Telegram (автопродление раз в 30 дней). Год — разовая оплата со скидкой.
- Пользователь отменяет подписку сам: *Настройки Telegram → Мои звёзды → Подписки*.
- Боту нужны команды `/paysupport` и `/terms` (они уже есть).
- Возврат: `/refund ID_пользователя ID_платежа` (ID платежа приходит вам в личку при каждой покупке).
- Группа живёт по тарифу того, кто добавил бота («спонсор»). Если лимит групп исчерпан, группа выключается до `/activate`.
- Вывод заработанных Stars: через Telegram (Fragment). Актуальные минимальную сумму, срок удержания и курс смотрите в документации Telegram, они меняются.

## Безопасность

- Каждый запрос мини-приложения проверяется по подписи Telegram (`initData`, HMAC-SHA256, срок до 24 ч). Подделать чужой ID нельзя.
- **RLS включён на всех таблицах без единой политики**: публичный ключ Supabase не читает ничего. Данные доступны только функциям, а они проверяют права: человек видит свои события и события групп, где он состоит.
- Вебхук бота защищён секретным токеном, планировщик — `CRON_SECRET`.
- Токены Google шифруются AES-256-GCM, ключ (`TOKEN_KEY`) лежит только в секретах функций.
- Ссылка-подписка ICS содержит случайный секрет (48 символов); её можно перевыпустить в настройках.
- Мы получаем от Telegram только ID. Телефон, email, геолокацию, контакты не запрашиваем.
- `/export` выгружает все данные человека, `/delete` стирает их (и отзывает токен Google). Записи об оплатах остаются для учёта и возвратов.

## Проверка активности (чтобы бесплатный проект не «уснул»)

Раз в 5 дней функция `cron` пишет вам в личку «Проверка активности» (с числом пользователей и событий) и обновляет запись в базе. Нажмите «Да, всё ок». Сам планировщик работает каждую минуту и тоже обращается к базе, так что это двойная страховка. Если сообщение не пришло больше 6 дней — проверьте проект в Supabase: он мог быть приостановлен, его можно восстановить кнопкой Restore.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Бот молчит | `curl https://api.telegram.org/botТОКЕН/getWebhookInfo` — смотрите `last_error_message`. Логи: Supabase → Edge Functions → bot → Logs |
| Мини-приложение «Не удалось войти» | `docs/config.js` (правильный REF?), `APP_URL`, токен бота в секретах |
| Нет уведомлений | `select * from cron.job_run_details order by start_time desc limit 5;` и логи функции `cron` |
| В группе бот не реагирует на обычные сообщения | BotFather → Group Privacy → Turn off, затем удалите и добавьте бота в группу заново |
| Google: «redirect_uri_mismatch» | URI в консоли Google должен совпадать буква в букву с `https://REF.supabase.co/functions/v1/google` |

## Структура проекта

```
docs/                       мини-приложение (GitHub Pages)
  index.html                весь интерфейс: 3 вида, 8 тем, настройки
  config.js                 адрес API
  GUIDE.md                  инструкция для пользователей (шаблон и 30 слов)
supabase/
  migrations/001_init.sql   таблицы + RLS
  cron.sql                  планировщик
  functions/
    bot/                    команды, группы, оплата, импорт .ics
    api/                    запросы мини-приложения
    cron/                   уведомления, продления, проверка активности
    google/                 возврат из Google OAuth
    ics/                    подписка для Apple/Google
    _shared/                тарифы, разбор фраз, время, Google, шифрование
scripts/setup-bot.sh        webhook, команды, кнопка меню
```
